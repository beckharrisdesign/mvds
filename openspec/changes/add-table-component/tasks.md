## 1. User outcomes (from spec scenarios)

- [ ] 1.1 **A screen-reader user navigates by column** — every cell is announced with its column header (`<th scope="col">`), row and column counts are available, and the accessible name resolves: a caption, or an `aria-label` when there is no caption; both-absent does not compile (D5)
- [ ] 1.2 **One cell holds a value much longer than the rest** — the 190-character `outputs-need-readers` description wraps inside a `60ch` measure, ids wrap at their hyphens inside `32ch`, the other columns keep usable widths, and the page never scrolls sideways (D1, D2)
- [ ] 1.3 **A table arrives with no rows** — the headers stay, and `TableEmpty` renders inside `<tbody>` with a consumer-authored title and one line at `py-32`; never a blank or collapsed box (D8)
- [ ] 1.4 **A table arrives with one more column than the design showed** — a sixth column is one more entry in the `columns` array; header, body and `colSpan` all read it, and no width is re-decided anywhere (D4)
- [ ] 1.5 **A wide table is viewed at S (480px)** — the region scrolls, the page does not; the header stays attached to its values; a keyboard user Tabs to the `role="region"` and scrolls it; the `border` scroll edge shows there is more (D3, D7, D10)
- [ ] 1.6 **The principles index renders 24 principles through Table** — four columns (ID · What it says · Enforcement · Source), `<th>` associated, provenance and enforcement legible, `enforced` as `Badge muted` and `guiding` as `Badge outline`, the long description no longer sharing a width fraction with a badge (D11, D12, D15)
- [ ] 1.7 **The component appears in the landing page's inventory** — after `npm run build` regenerates the snapshot, `Table` is in the Component library's UI list and the tally increments, with no hand-maintained list touched and no page layout changed

## 3. Implementation

- [ ] 3.1 **`src/components/ui/table.tsx`** via `npx shadcn@latest add table`, then the MVDS tuning pass. Parts: `Table` (`w-full`, props `rules` = `"horizontal" | "vertical" | "both" | "none"` default `horizontal`, `striped` boolean — D16, D17), `TableCaption` (`text-small text-muted-foreground px-16 pb-16`, `caption-side: top`), `TableHeader` (`sticky top-0 bg-table-surface` — D3, D14), `TableBody`, `TableRow` (`border-b border-border` under `rules` horizontal/both; `tbody` rows only: `hover:bg-primary-2`, and `even:bg-primary-1` when `striped` — D6, D17), `TableHead` (`<th scope="col">`, `text-caption text-muted-foreground p-16 align-top text-left` — D13, D15, D18), `TableCell` (`text-body text-foreground p-16 align-top`, `border-r border-border` on all but the last under `rules` vertical/both — D13, D16, D18). shadcn's off-grid metrics (`p-2`, `h-10`, `align-middle`) are replaced, not kept. No `mvds-allow` anywhere in the file.
- [ ] 3.2 **`TableEmpty`** in `table.tsx`: `<td colSpan>` with `py-32`, centred, a required `title` and an optional `hint`, `Type/Body` + `Type/Small muted-foreground`, gap `space-4`. MVDS ships no default copy (D8).
- [ ] 3.3 **`TableScrollRegion`** in `table.tsx`: `role="region"`, `tabIndex={0}`, `overflow-x-auto`, an optional `maxHeight` expressed as a `max-h-*` class (a max, never a height), and the accessible-name contract as a discriminated prop type — `{ "aria-labelledby": string } | { "aria-label": string }` — so both-absent is a type error (D5). Scroll edges as CSS-only `background-attachment: local` cover gradients in `--table-surface` over edge gradients in `--border` fading to transparent, in `src/index.css` as a utility or a `[&]` class on the region, no JS (D7).
- [ ] 3.4 **`--table-surface` token** (D14): `:root` and `.dark` in `src/index.css` declare `--table-surface: var(--background)`; `@theme inline` maps `--color-table-surface` so the utility is `bg-table-surface`; `Card`'s root adds `[--table-surface:var(--card)]` as a one-class tuning edit. `npm run check:contrast` must still pass — if its parser does not resolve a `var()` alias, extend the resolver in `scripts/lib/` with a case that fails without it rather than excluding the token; no new pairing is added (D14 states why). `npm run check:figma` must pass with the token recorded as **not yet mirrored** in whatever record the gate reads for that state (`figma/conventions.mjs` / `figma.lock.json`), with the reason "`Color/table-surface` lands on the next requested token sync" — never by hand-adding a variable to the lock.
- [ ] 3.5 **Exports**: the eight parts (`Table`, `TableCaption`, `TableHeader`, `TableBody`, `TableRow`, `TableHead`, `TableCell`, `TableEmpty`) and `TableScrollRegion` from `src/index.ts`.
- [ ] 3.6 **`src/components/ui/table.stories.tsx`** (`title: "UI/Table"`, `tags: ["autodocs"]`). Rows are **derived from the real manifest** (`manifest-snapshot.json` principles), never a hand-written fixture (D9): `Default` (five rows, caption, header), `Empty` (0 rows, `TableEmpty`), `OneRow`, `ManyRows` (50 rows by repeating the set, inside a `TableScrollRegion` with a `max-h`, sticky header visible in the scrolled state — the Risks section names why the story must render *scrolled*, not just the top), `Long` (the measured 190-character record), `Wide` (one added column, `colSpan` following), `Narrow480` (`parameters.viewport` at S, contained scroll, the region focusable), `Rules` (vertical, both, none side by side), `Striped` (with a hovered row, so stripe and hover are seen together), `InlineContent` (the two-line identity row: name + e-mail, a `Badge` on the line box, a right-aligned numeric cell — D13).
